<objective>
Route one injected worker crash through a central stop that releases keys, saves a clip, publishes a structured incident, and starts a repeating alarm, then make acknowledgment and worker restart independent of the dead worker.

Purpose: A failure in the capture or input path must strengthen the safe state rather than taking the debugger, recording evidence, or alarm down with it.
Output: Idempotent cross-thread safe_stop, explicit severity registry, packaged alarm with fallback, sticky stop UI, direct acknowledgment, and fresh-worker recovery.
</objective>

<interfaces>
From Plan 01:
- Controller stop advances a cancellation generation, resolves queued/in-flight ActionOutcomes, and releases every held key.
- Controller failures can be reported outside internal locks without permitting another key-down.

From Plan 02:
- `FrameEncoder.flush_through(sequence, timeout)` returns a bounded complete/incomplete result.
- `SessionRecorder.trigger(reason, now)` is cross-thread safe and returns a clip path even for a one-off clip.

Existing behavior to replace:
- `Application._stop(reason)` duplicates partial terminal effects and worker `finally` calls only `controller.stop`.
- `__main__` currently exits when `app.worker.is_alive()` becomes false, which destroys the debugger after a crash.
</interfaces>
</context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker/watchdog/debugger threads -> safe_stop | Multiple failure domains race to mutate real input, recording, status and alarm state. |
| runtime -> Windows audio | Alarm output crosses to a local OS side effect that must not delay key release. |
| localhost debugger -> acknowledge/restart | Token-protected operator commands can silence an alarm or create a new capture worker. |

## STRIDE Threat Register (ASVS L1; block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Tampering | stop reason/severity routing | high | mitigate | Use typed StopSeverity plus a stable code registry, never message parsing, and tests covering every D-09 code and default-rejecting unknown callers. |
| T-01-08 | Denial of Service | cross-thread safe_stop/alarm/encoder | high | mitigate | Release/cancel first; idempotent stop lock; bounded encoder flush; non-blocking async WAV; event-wait fallback; bounded joins; publish incomplete sub-effects without aborting safety. |
| T-01-09 | Elevation of Privilege | worker restart/input authority | high | mitigate | Direct restart always creates IDLE disabled state, drains queues, clears probes/re-verification, refuses duplicate worker creation, and never arms. |
| T-01-10 | Spoofing | debugger acknowledge/restart | high | mitigate | Retain loopback Host and X-Debug-Token checks, dispatch only exact named direct methods, and expose incident id/state for stale-click rejection. |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | No external package is installed; winsound/threading/importlib resources are standard-library facilities and the WAV is repository-owned package data. |
</threat_model>
