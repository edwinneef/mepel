Purpose: Later timers and movement verification depend on capture-time decisions being reproducible, while operators need frame-stage timing that excludes image encoding.
Output: Deterministic policy records, strict replay diff CLI, bounded frame encoder, thread-safe recorder terminal barrier, and per-stage timing snapshots.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| recorder JSONL -> policy replay | Disk records are untrusted structured input that can influence offline policy state and CI verdicts. |
| capture worker -> frame encoder | Mutable image arrays and status cross threads through a bounded queue. |
| frame encoder -> recorder/debugger | Encoded screenshots and decisions cross into disk and localhost presentation surfaces. |

## STRIDE Threat Register (ASVS L1; block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Tampering | policy-only replay input | high | mitigate | Validate required fields, finite monotonic capture-relative time, strictly increasing sequence, explicit policy snapshot version, and fail on malformed/legacy records rather than coercing them. |
| T-01-05 | Denial of Service | `FrameEncoder` and recorder queues | high | mitigate | Bound frame queue to one, use replace/drop accounting, bound terminal flush and thread joins, and surface encoder failure without blocking safety actions. |
| T-01-06 | Information Disclosure | encoded screenshot/recording output | medium | mitigate | Preserve existing repo-local data directory and retention path, never add external upload/network output, and keep offline replay separate from gameplay input. |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan uses only Python standard-library concurrency plus installed project dependencies; no package-manager install or third-party addition is permitted. |
</threat_model>
